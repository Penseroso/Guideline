# 답변 적합성 평가 질문 설계

문서 상태: 검증 기준 v1

작성일: 2026-09-02

대상: 현재 구조화된 6개 가이드라인 번들

2026-09-03 실제 50문항 실행·수동 판독 결과와 구현 후 재검증은 `history/verification/answer_suitability_audit_2026-09-02.md`에 기록했다.

## 1. 결론: 데이터 레이어 보강을 먼저 해야 하는가

50문항 설계와 1차 실행을 위해 원천 데이터 모델을 먼저 바꿀 필요는 없다. 현재 아카이브에는 문서·절 계층, 원문 단위, 의미 레코드, 정량 기준, 조건·예외 및 교차참조가 분리되어 있어 원자적 근거와 절 단위 개요를 검증할 수 있다.

다만 현재 모델은 답변 구성에 필요한 다음 정보를 직접 표현하지 않는다.

- 문서 또는 절의 근거 기반 요약
- 여러 레코드 사이의 절차 순서, 대안, 선후관계 및 비교 차원
- broad 질문에서 먼저 보여줄 핵심 근거와 펼쳐 볼 보조 근거의 우선순위
- 특정 주제에 필요한 근거가 모두 구조화되었는지를 나타내는 완결성 표지
- 질문의 범위 수준과 그에 맞는 답변 형식

따라서 먼저 50문항을 실행해 실패 패턴을 수집한다. 같은 결함이 여러 문서와 질문에서 반복될 때만, 원본 번들을 오염시키지 않는 파생 레이어로 `topic`, `relation`, `salience`, `coverage` 같은 필드를 검토한다. 개별 질문별 답변 문구나 정답을 데이터에 저장해서는 안 된다.

## 3. 적합성 채점 계약

각 문항을 다음 7개 차원에서 0~2점으로 평가한다.

1. **범위 적합성**: 질문보다 지나치게 좁거나 넓지 않은가.
2. **내용 완결성**: 질문 수준에서 필요한 주요 항목을 빠뜨리지 않았는가.
3. **구조 적합성**: 개요·절차·기준·예외·비교에 맞는 형식을 사용했는가.
4. **구체성 조절**: broad 질문에는 방향을, detail 질문에는 실제 기준을 주는가.
5. **조건·예외 보존**: 조건부 내용을 절대 기준처럼 말하지 않는가.
6. **근거 정합성**: 모든 주장에 해소 가능한 원문 근거가 있고 근거가 실제 주장을 지지하는가.
7. **UX 표현 적합성**: route와 질문 깊이에 맞는 화면 계층을 사용하고, 근거를 읽기 전에 가이드라인과 섹션을 식별할 수 있는가.

다음은 총점과 무관한 치명적 실패다.

- 질문과 다른 문서·기술·대상군의 기준을 답함
- broad 질문에 관련 chunk만 나열하고 종합 설명이나 전체 구조를 제공하지 않음
- detail 질문에서 필요한 수치, 분모, 조건 또는 예외를 생략함
- 원문이 예시·권고·기본값인 내용을 절대 요건으로 바꿈
- 근거 없는 규제 적합성 판단, 연구 설계 권고 또는 Go/No-Go 결론을 생성함
- 근거 카드가 원문부터 시작하고 해당 가이드라인·섹션을 뒤늦게 또는 불명확하게 표시함

### UI 표현 계약

- 모든 근거 단위는 본문보다 먼저 `가이드라인 코드 → 섹션 번호 → 섹션 제목`을 헤더로 표시한다.
- `grounded_generation`은 하나의 생성형 답변 면을 먼저 제공하고, 그 아래에 출처 헤더가 있는 구조화 근거를 둔다.
- `section_overview`는 상위 절 개요 뒤에 직접 하위 절을 헤더로 나누고, 설명과 정량 기준을 분리한다.
- `source_excerpts`는 생성형 답변처럼 보이지 않는 원문 목록을 사용하되 각 원문 앞에 출처 헤더를 둔다.
- `comparison`은 문서별 열 또는 공통 비교축을 사용하고 어느 근거가 어느 문서에 속하는지 시각적으로 섞이지 않게 한다.
- `refusal`은 빈 답변이나 오류 카드가 아니라 거절 이유와 아카이브 범위를 설명한다.
- 세부 근거의 source unit ID와 PDF 링크는 추적 정보로 유지하되, 가이드라인·섹션보다 높은 시각적 위계를 갖지 않는다.

준비도 표시는 `R`(현재 구조로 직접 검증 가능), `D`(파생 의미 레이어 후보), `A`(원자적 추출 완결성도 함께 감사 필요)를 뜻한다. `D`와 `A`는 답변 실패를 미리 확정하는 표지가 아니다.

## 5. 실행 순서

1. 50문항을 현재 엔진에 그대로 실행해 route, mode, 인용 문서·절, 답변 전문을 저장한다.
2. 자동 테스트는 문서/절 범위, 인용 해소, 필수 숫자와 하위 절 완결성 회귀만 담당한다.
3. 답변 적합성 7개 차원은 전체 envelope, 원문 근거와 실제 UI를 에이전트가 직접 판독한다.
4. 실패를 `retrieval`, `coverage`, `composition`, `scope`, `presentation`으로 분류한다.
5. 세 개 이상 서로 다른 질문·문서에서 반복되는 결함만 일반 규칙 또는 파생 데이터 모델 변경 후보로 올린다.
