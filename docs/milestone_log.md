## M5 — Local-first production MVP

Core MVP completed 2026-08-28; semantic routing and route-specific presentation revised through 2026-09-08. The HTTP/API contract names the actual outcomes (`structured`, `grounded_generation`, `source_excerpts`, `refusal`) instead of A/B paths. Broad questions now use document/section/topic coverage, process and within-document comparison modes; generated answers are bounded by structured claims and checked for scope coverage. The UI exposes route/mode, supports an API override, presents generated synthesis above section-headed evidence, and renders section overviews, processes, comparisons, excerpts, and refusals distinctly. A 50-question Korean broad-to-detail audit reduced unsuitable answers from 27 to 5 without question-specific answer storage. A 2026-09-07 follow-up closed the remaining Q06 candidate-selection gap and replaced implicit trust of KnowledgeRecord Korean strings with fail-closed, hash-bound review attestations covering all answerable record types. On 2026-09-08 Stage D0 migrated the semantic overlay/public answer contracts to `0.2.0`/`2.2.0`, then expanded the reviewed semantic inventory to a final de-duplicated 55 manifests (6 document overviews + 42 parent sections + 5 leaf topics + 2 specialized manifests); deterministic 55/55 selection verification and a fresh 50/50 live audit retained 16 suitable/34 partial/0 unsuitable with no regression in the established 16 suitable cases. Stage D left `summary_specs`, Korean presentation sentences, and `salience_profiles` unconnected at runtime; Stage E activates each separately, starting with Stage E0 (2026-09-08), which added the `review_status` field `salienceProfile` was missing (overlay contract `0.2.0` → `0.3.0`) so it can be gated `reviewed`/`needs_review` like every other overlay object. Stage E1 (2026-09-08) then wired `summary_specs` structure into served coverage disclosure (public answer contract `2.2.0` → `2.3.0`): the offline attachment audit confirmed all 5 existing pilot summary_specs reach their intended manifest. Stage E2 (2026-09-08) rendered the matching Korean presentation sentence for section/topic overview answers (contract `2.3.0` → `2.4.0`) and added evidence-freshness filtering for the presentation overlay at load time (previously checked only by the validator). Stage E3 (2026-09-08) fixed a dead-code bug in salience's document-level matching and wired `salience_profiles` into exposure tiers (primary/supporting shown, detail collapsed; contract `2.4.0` → `2.5.0`), completing Stage E's wiring for all three objects Stage D left unconnected. A live 50-question audit against the current codebase (`.env` API keys confirmed working) promoted all of Stage E0–E3's objects to `reviewed` (5 summary_specs, 3 presentation entries, 7 salience_profiles) with the established 16 suitable cases unregressed — one case (Q25) showed a differing `grounded_generation` claim on rerun, confirmed via reproduction and content review to be model-generation variance unrelated to any Stage E code change (`history/decision_log/review_log.md` REV-015). Stage F (2026-09-08) then mechanically extended `summary_specs`/`salience_profiles` (structure only, no engine change, no new Korean text) to the 47 manifests Stage D added but Stage E's pilot scope didn't cover — 45 new summary_specs (multi_criterion/comparison manifests excluded, no matching summary shape) and 19 new salience_profiles (manifests with 5+ facets, tier/rationale derived from each facet's existing reviewed semantic_role). Korean presentation text for these 45 remains unauthored (`text: null`, same fallback as Stage E2) — deferred to separate manual work since many parent sections have no directly-filed content of their own to quote and new synthesis carries accuracy risk. A follow-up review found the initial promotion had reused a pre-activation live audit, which cannot show what Stage F's own disclosure looks like once active; the promotion tooling was hardened with a semantic-state fingerprint that rejects a stale audit, and a fresh post-activation 50-question audit confirmed 15/16 established-suitable cases exact and all 43 summary/27 salience occurrences across 50 live answers attached to a topically-correct manifest with no coverage gap hidden behind salience collapsing (zero `detail`-tier items exist in the current dataset). `validate:semantic` was added to CI, and the one high-severity `npm audit` finding (`fast-uri`, unreachable in this codebase's schema usage) was fixed with a non-breaking patch bump.

Stage G (2026-09-08) completed Korean semantic presentation coverage for all 50 applicable reviewed `summary_specs` across the six documents: 47 new entries plus 3 migrated entries, each independently verified and bound to both source-evidence hashes and a summary-spec hash. Thirteen S6(R1) facets with no structured records remain explicit `no_structured_evidence` gaps and are never inferred as content. The post-activation 50-question audit matched the current semantic-state fingerprint and retained all 16 established suitable cases' route, mode, and claim-ID sets relative to the Stage F baseline; the public answer contract remains `2.5.0`.

A same-day follow-up closed all 13 of Stage G's S6(R1) gaps: the 13 facets (Biological Activity/PD, Administration/Dose Selection, Exposure Assessment, Single Dose Toxicity, Immunotoxicity, Reproductive Performance/Developmental Toxicity, Carcinogenicity, Local Tolerance, and Part II §§3.4/5.1–5.4) were extracted, structured, and independently verified against the source PDF, then their 4 presentation entries re-authored — `scripts/audit_semantic_presentation.js` now reports 0 explicit gaps. The extraction pass also found and fixed a real `engine/extraction_agent.js` prompt bug (`normalized_ko` had no instruction to actually be Korean, so the first backfill pass produced English text throughout) and two schema-shape bugs, all caught by independent verification and corrected before promotion, not after. The Corpus grew from 1,353 to 1,495 reviewed KnowledgeRecords and from 2,484 to 2,693 Korean presentation entries (`docs/verification_status.md`).

The promotion tooling was then hardened, independent of any specific stage: `scripts/semantic_promotion_lifecycle.js` gained an explicit prepare → [fresh live audit, run separately] → verify → finalize/rollback lifecycle (`prepareTargetState`/`verifyAndFinalizePromotion`/`rollbackPreparedState`), replacing every `promote_semantic_stage_*.js`/`promote_semantic_presentation.js` script's prior single-invocation flip-then-verify (the exact shape that produced Stage F's original pre-activation-audit mistake, corrected by hand at the time). Each script keeps its no-flag default behavior for backward compatibility; `--prepare`/`--verify`/`--rollback` add the split lifecycle a real live audit generated between prepare and verify requires. The established-16-suitable-case regression guard (`evaluateEstablishedCase`) was generalized by route rather than special-cased for Q25: a deterministic route still requires exact claim-set equality, while `grounded_generation` (10 of the 16) keeps route/mode/`answered`/grounding as hard requirements and records a claim-set difference as a diagnostic — resolving the open follow-up recorded against Q25's three independently-reproduced claim-set variants (`history/decision_log/review_log.md` REV-015) without narrowing the gate for anyone. `test/semantic_promotion_lifecycle.test.js` (13 tests) exercises both the policy (against Q25's real recorded data) and the full lifecycle (prepare/rollback/verify/finalize, including stale-fingerprint rejection) against temp fixtures — `data/derived/` is never touched by the test run.

A separate production cleanup pass archived ~50 one-time extraction/cleanup/migration scripts with no remaining `package.json` or `require()` references to `history/build_scripts/` (see its own `README.md`), renamed `scripts/retest_m2_queries.js` to `scripts/replay_query_log.js` (the function is generic, "M2" was a stale milestone label), and corrected several now-inaccurate "pilot"-era references in `README.md`, `AGENTS.md`, `docs/schema.md`, and `history/README.md` left over from the `data/pilots/` → `data/guidelines/` rename.
